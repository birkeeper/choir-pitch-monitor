Backend parity

Runs the same audio through the salience model on every available TF.js backend and compares the results against the CPU backend, which is the reference. This catches a backend computing the model wrongly rather than merely slowly — a failure mode that has been observed in TF.js's WebGL convolutions, that produces plausible-looking output rather than an error, and that a small synthetic input does not necessarily trigger.

Run this in a real browser tab, not headless. Headless Chrome frequently cannot obtain a WebGPU adapter, so WebGPU goes untested there. Worth re-running after any change of model, GPU or TF.js version.
